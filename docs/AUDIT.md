# Application audit — October 27, 2026

The audit compared the current Next.js application with all ten archived prototype files, their feature inventory and the master requirements. Attached prototype material was treated as reference data. Original source files and all ten derived illustrations still match the preservation manifest. No production property data was replaced with hardcoded runtime listings, and no historical draft was published.

## Audit fixes

- Failed password/OAuth sign-in retains a validated return path. Google options beside inquiry forms return to the current page and show pending state. Password length is checked before calling Auth. Code-exchange failures produce a safe error redirect; failed sign-out is visible.
- Repeated query values are normalized where string operations are required. Invalid numeric filters are ignored safely. Malformed staff record IDs show a CRM missing-record state, and inherited object keys cannot render empty journal articles.
- Inquiry history uses a dedicated `/admin/inquiries/[id]` route, fixing links to records beyond the first list page. Related inquiry/inbox contact data no longer depends on fetching a globally capped lead/property directory. Related-query failures are surfaced and team management is paginated.
- Notes support text editing/deletion in lead and conversation detail. Migration 006 prevents changing their identity, author, creation timestamp or originating record after insertion; text changes still generate audits.
- Property deletion/photo removal checks Storage results before the final database operation. A Storage rejection retains the record and displays a retryable error. Only persisted images belonging to that property are candidates for removal.
- Existing human conversations remain accessible when automated chat is disabled. Stale conversation history stops polling after a 404, and chat writes explicitly disable caching.
- Added root loading and staff missing-record states. Legal contact details use shared company settings. Conceptual artwork is retained and disclosed without internal placeholder instructions.
- Fixed a neighborhood-count serialization regression found by the audit browser run; added a server/client-boundary regression test. Scoped test ingress headers to localhost so they do not interfere with external fonts/images. Stabilized visual captures after actual page content, font loading and finite entrance animations. Compact mobile chat controls avoid covering the home-search form; the duplicate native menu marker is hidden.

Obtain business approval for historical statistics, broker claims, testimonials, legal copy and journal material. Original journal article bodies and photography were not supplied; short editorial additions and labeled illustrations are not substitutes for approved publication content.
4. Outbound email/SMS and calendar booking are not implemented. The app persists requests for staff follow-up. Configure notification delivery separately if required.
5. AI candidate search considers up to 100 recently updated published properties; both chat views show the latest 200 messages while all messages stay in the database. Provider availability/quotas are external dependencies. Full original animation/modal parity, unread metadata, suggested-prompt editing/preview, dashboard historical comparisons and approved lead scoring remain documented prototype differences.
6. Storage and PostgreSQL cannot share an atomic transaction. Retry reported cross-service failures and inspect files after repeated failures; an image removed successfully before a subsequent database failure can require reconciliation. This audit does not claim transactionality across services or that every external outage was fault-injected through the UI.
